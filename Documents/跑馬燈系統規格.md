## ■ 0. 系統概述

跑馬燈是榮耀系統的**公開曝光機制**之一：把玩家的高價值事件（贏分、成就、進榜等）廣播給其他玩家看，製造「被看見」與「比較心理」。

跑馬燈的顯示方式有**兩種**：

| # | 顯示方式 | 位置 | 角色 |
|---|---|---|---|
| 1 | **活躍玩家資訊** | 使用者資訊（狀態列）的**右方** | 高頻、輕量的玩家動態輪播 |
| 2 | **一般顯示** | 獨立的跑馬燈區塊（畫面上方懸浮） | 低頻、高價值事件的正式廣播 |

- 同一事件若同時符合兩區條件（如贏分 ≥ 20 倍），**兩區皆顯示**。
- 玩家**自己**的事件在自己畫面的兩個顯示區也**照常顯示**。

## ■ 1. 介面操作

### 1.1 活躍玩家資訊（使用者資訊右方）

| 項目 | 規則 |
|---|---|
| 位置 | 使用者資訊（狀態列）右方 |
| 顯示節奏 | **每 3 秒顯示一則**，依序輪播 |
| 玩家操作 | —（純展示，無操作） |

#### 收錄範圍（顯示內容來源）

**同一個母代理**之下的玩家行為，皆列入顯示內容：

| # | 事件類型 | 說明 |
|---|---|---|
| 1 | 任何贏分 | 玩家有贏分即列入，**不設門檻**（任何金額 / 倍數皆收錄） |
| 2 | 完成每日任務 | 當日**全部**每日任務皆完成的當下列入一次（非每完成一筆就列入） |

#### 顯示內容（每則訊息的版面）

每則訊息為**兩行式**：上行為玩家資訊，下行為訊息文字。

- **玩家資訊比照「玩家 Chip」樣式**：玩家目前背板為底色 + 等級徽章 + 稱號 + 玩家名稱（同現行活躍玩家面板呈現）。

| 事件類型 | 顯示格式 | 範例 / 說明 |
|---|---|---|
| 贏分 | 〔玩家資訊〕<br>`Win x{倍數}` | 如 `Win x34`。**只顯示贏分倍數，不顯示贏分數值（金額）** |
| 完成每日任務 | 〔玩家資訊〕<br>`Daily Tasks Complete` | 固定文案（英文字串為暫定示意，正式文案待企劃拍板） |

> **跑馬燈內文案統一使用英文**（含活躍玩家資訊與一般顯示）；文中英文字串除 `Win x{倍數}`、`entered the top 50` 外皆為暫定示意。

#### 訊息保留規則（佇列上限）

- **不要求即時顯示**：訊息允許延遲，不需要事件發生當下立刻播出。
- 保留範圍：**1 分鐘內**的訊息，或最多 **20 則**。
- 超過保留範圍的**舊訊息不再顯示**（直接捨棄，不補播）。
- **上限為約略值**：「1 分鐘」「20 則」不要求精確執行，實際做法交由程式決定；不必為了精準到秒 / 精準則數而做過度即時、浪費效能的處理。

### 1.2 一般顯示（獨立跑馬燈）

#### 顯示條件（觸發來源）

| # | 觸發條件 | 觸發時機 | 顯示方式 |
|---|---|---|---|
| 1 | **贏分在 20 倍以上** | 單局贏分倍數 ≥ 20x | 〔使用者資訊〕〔遊戲名稱〕`Win x{倍數}`（如 `Win x34`） |
| 2 | **排行榜進入前 50 名** | 從 50 名**外**上升到 50 名**內**才顯示；已在 50 名內的名次變動**不顯示**。**僅適用通用總排行榜（含其下各指標榜），遊戲各別排行榜不列入** | 〔使用者資訊〕〔排行榜名稱〕`entered the top 50` |
| 3 | **完成週打卡** | 玩家於每日任務頁**領取週獎勵**的當下觸發 | 〔使用者資訊〕`Weekly Check-in Complete`（暫定文案） |
| 4 | **完成月打卡** | 玩家於每日任務頁**領取月獎勵（月全勤獎）**的當下觸發 | 〔使用者資訊〕`Monthly Check-in Complete`（暫定文案） |
| 5 | **系統公告** | 由系統 / 營運發出 | 公告文字（無玩家資訊） |

- **廣播範圍＝同一母代理**（與活躍玩家資訊一致）。
- **多榜同時進榜**：玩家一個行為可能同時進多個指標榜，**每榜各發一則**，不過濾、不做合併判斷。
- **月重置靜默期**：每月排行榜重置會造成大量玩家同時「重新上榜」，故**重置後 6 小時內不顯示上榜訊息**；若靜默期後上榜訊息依然過於頻繁，再**抬高條件或新設其他條件**。
- 週 / 月打卡的觸發點是「**領取獎勵**」而非「達成條件」：達成但未領取不廣播；**次月補領上月獎勵時同樣觸發廣播**（打卡規則見 `每日任務系統規格.md`）。
- 〔使用者資訊〕比照玩家 Chip 樣式（背板底色 + 等級徽章 + 稱號 + 玩家名稱）。
- **系統公告**用於：**維護通知、活動通知、系統通知**。屬營運側訊息，非玩家事件，訊息內不帶玩家資訊。
- 系統公告**第一階段只做 API 新增功能，暫無後台畫面可操作**（資料項見 §3e）。

#### 播放與動畫

- **常態播放節奏：每 3 秒顯示一則**。
- 動畫流程沿用 `榮耀系統實作規格.md` §8 的開合形式：收合 → 彈跳展開 → 內容右至左單次滑動 → 收合 → 播下一則；各段時長配合 3 秒節奏調整（§8 原列的約 6s 滑動等為 prototype 舊預設，以本文件 3 秒節奏為準）。
- 每次只播 1 則；空隊列維持收合、不顯示空容器。

#### 訊息堆積（設計警訊）

- **設計面不希望出現堆積**：每 3 秒一則的常態節奏下，若實際運行仍常態性堆積，應**考慮提高顯示條件**（如調高贏分倍數門檻），而不是讓佇列無限變長。

## ■ 2. 功能流程

### 2.1 活躍玩家資訊

1. 同母代理下任一玩家發生**贏分**或**完成當日全部每日任務** → 該事件進入待播清單。
2. 待播清單套用保留規則：僅保留 **約 1 分鐘內**、至多**約 20 則**；超出者捨棄（約略值，做法由程式決定）。
3. 顯示區**每 3 秒**輪播一則。
4. 無待播訊息時 → **停留顯示最後一則**（不清空、不隱藏）。

### 2.2 一般顯示（獨立跑馬燈）

1. 任一玩家觸發顯示條件（§1.2 五種之一）→ 該訊息進入跑馬燈佇列。
2. 跑馬燈**依訊息到達順序**播放（不做優先序），**常態每 3 秒一則**：展開 → 滑動顯示該則 → 收合 → 播下一則。
3. 排行榜類：**僅通用總排行榜列入判定，遊戲各別排行榜不列入**。玩家**從 50 名外上升到 50 名內**的瞬間觸發一次；之後在 50 名內的名次升降**不再觸發**（再次掉出 50 名外、又重新進入時，重新觸發）。一個行為同時進多個指標榜 → 每榜各發一則，不過濾。**每月排行榜重置後 6 小時內不顯示上榜訊息**。
4. 週 / 月打卡類：玩家點擊「領取」週獎勵 / 月全勤獎時觸發。
5. 系統公告類：由系統 / 營運透過 **API** 發出（維護、活動、系統通知），進入同一佇列播放；第一階段無後台畫面。
6. 若常態節奏下仍出現常態性堆積 → 屬設計警訊，應檢討並提高顯示條件。

## ■ 3. 資料設定

### 3a. 活躍玩家資訊 — 每則訊息需具備的資訊

| 資料項 | 意義 |
|---|---|
| 玩家身分 | 發生事件的玩家；顯示比照玩家 Chip（背板 + 等級 + 稱號 + 名稱） |
| 事件類型 | 贏分 / 完成每日任務 |
| 事件內容 | 顯示文字（贏分＝倍數，如 `Win x34`；每日任務＝固定英文文案，暫定 `Daily Tasks Complete`） |
| 發生時間 | 用於「1 分鐘內」保留判定 |

### 3b. 活躍玩家資訊 — 規則參數（展示用預設值）

| 參數 | 值 |
|---|---|
| 收錄範圍 | 同一母代理下的所有玩家 |
| 收錄事件 | 任何贏分、完成當日全部每日任務 |
| 贏分收錄門檻 | 無（不設門檻） |
| 無待播訊息時 | 停留顯示最後一則 |
| 即時性要求 | 低（允許延遲，非即時推播） |
| 訊息保留時間 | 約 1 分鐘 |
| 訊息保留上限 | 約 20 則 |
| 上限精確度 | 約略值即可，做法由程式決定；不為精準值做過度即時 / 浪費效能的處理 |
| 超出保留範圍 | 舊訊息不顯示（捨棄，不補播） |
| 輪播節奏 | 每 3 秒一則 |

### 3c. 一般顯示 — 每則訊息需具備的資訊

| 資料項 | 意義 |
|---|---|
| 玩家身分 | 觸發事件的玩家；顯示比照玩家 Chip（背板 + 等級 + 稱號 + 名稱）。**系統公告無此項** |
| 事件類型 | 高倍贏分 / 進排行榜前 50 / 完成週打卡 / 完成月打卡 / 系統公告 |
| 遊戲名稱 | 高倍贏分類需顯示（發生在哪款遊戲） |
| 排行榜名稱 | 進榜類需顯示（進入哪個排行榜）；名稱定義**以排行榜文件為準**（本文件不另定義） |
| 事件內容 | 顯示文字（見 §1.2 顯示方式欄；系統公告＝公告文字本身） |

### 3d. 一般顯示 — 規則參數（展示用預設值）

| 參數 | 值 |
|---|---|
| 廣播範圍 | 同一母代理下的所有玩家（與活躍玩家資訊一致） |
| 贏分廣播門檻 | 贏分倍數 ≥ **20x**（只看倍數，不看金額） |
| 排行榜進榜門檻 | 進入前 **50** 名（從 50 名外 → 50 名內才觸發；榜內名次變動不觸發） |
| 排行榜適用範圍 | 僅**通用總排行榜**（含其下各指標榜）；遊戲各別排行榜不列入 |
| 多榜同時進榜 | 每榜各發一則，不過濾、不做合併判斷 |
| 月重置靜默期 | 排行榜每月重置後 **6 小時內**不顯示上榜訊息 |
| 靜默期後仍頻繁 | 抬高條件或新設其他條件（設計面調整，非程式自動處理） |
| 播放順序 | 依訊息到達順序，不做優先序 |
| 週打卡觸發點 | 玩家**領取週獎勵**當下（非達成當下） |
| 月打卡觸發點 | 玩家**領取月全勤獎**當下（非達成當下） |
| 補領處理 | 次月補領上月週獎 / 月全勤獎時，**同樣觸發廣播** |
| 文案語言 | 跑馬燈內**統一英文**（正式字串待企劃拍板，文中英文為暫定示意） |
| 過長文字處理 | 訊息過長時截斷顯示 `…`；玩家名稱長度由**更名機制**控管（2-12 字元），不在本系統另設限 |
| 系統公告用途 | 維護通知、活動通知、系統通知（營運側發出，無玩家資訊） |
| 播放節奏 | **每 3 秒一則（常態）**；動畫開合形式沿用 `榮耀系統實作規格.md` §8，各段時長配合 3 秒節奏 |
| 堆積處理 | 設計上不希望堆積；常態節奏下仍常態性堆積 → 考慮提高顯示條件 |

### 3e. 系統公告 — 資料項與操作（API，暫無後台畫面）

> 第一階段以 API 提供公告操作，營運後台畫面為未來規劃。
> 支援操作：**新增、更新、移除**——更新與移除皆以**公告識別碼**指定對象。

| 資料項 | 型態 | 意義 |
|---|---|---|
| 公告識別碼 | 字串 | 識別這則公告（更新 / 移除時對應用） |
| 公告訊息 | 字串 | 跑馬燈顯示的公告文字 |
| 持續時間 | 整數 | 這則公告**持續多久**，單位為**秒**；期間內公告有效。**預設值：10 分鐘（600 秒）** |
| 頻率 | 整數 | **每 N 秒插播一次**，直到持續時間結束。**預設值：20 秒** |

| D16 | 系統公告操作方式 | 第一階段只做 **API 新增公告**，暫無後台畫面；資料項＝識別碼、訊息、持續時間（預設單位秒）、頻率 |
| D17 | 一般顯示播放節奏 | **常態每 3 秒顯示一則**（非堆積時才啟用）；設計上不希望堆積，常態性堆積應考慮提高顯示條件 |
| D18 | 解鎖稱號 / 里程碑成就廣播 | **取消**（原實作規格 §8.1 所列，本版不做） |
| D19 | 播放順序 | 依訊息到達順序播放，不做優先序 |
| D20 | 進榜判定適用範圍 | 前 50 名僅適用**通用（全部）排行榜**；遊戲各別排行榜不列入 |
| D21 | 系統公告「頻率」定義 | **每 N 秒插播一次**，直到持續時間結束 |
| D22 | 一般顯示廣播範圍 | 同一母代理（與活躍玩家資訊一致） |
| D23 | 活躍玩家資訊「完成每日任務」觸發點 | 當日**全部**每日任務皆完成的當下列入一次（非每完成一筆就列入） |
| D24 | 雙區重複曝光 | 同一事件符合兩區條件時兩區皆顯示；玩家自己的事件在自己畫面照常顯示 |
| D25 | 系統公告 API 操作 | 支援**新增 / 更新 / 移除**，更新與移除以公告識別碼指定對象 |
| D26 | 文案語言 | 跑馬燈內**統一使用英文**；正式字串待企劃拍板（文中英文文案為暫定示意） |
| D27 | 過長文字處理 | 訊息過長截斷顯示 `…`；玩家名稱長度由更名機制控管，本系統不另設限 |
| D28 | 補領廣播 | 次月補領上月週獎 / 月全勤獎時，同樣觸發廣播 |
| D29 | 多榜同時進榜 | 一個行為同時進多個指標榜 → 每榜各發一則，不過濾、不多做判斷 |
| D30 | 月重置靜默期 | 排行榜每月重置後 **6 小時內**不顯示上榜訊息（避免大量同時上榜灌爆跑馬燈） |
| D31 | 靜默期後仍頻繁 | 屬設計面調整：抬高條件或新設其他條件 |
| D32 | 排行榜名稱 | 〔排行榜名稱〕顯示文字以**排行榜文件**定義為準，本文件不另定義 |
| D33 | 系統公告預設值 | 持續時間預設 **10 分鐘（600 秒）**；頻率預設 **20 秒** |

## ■ 5. QA 驗收清單

### 活躍玩家資訊

- [ ] 活躍玩家資訊顯示於使用者資訊右方。
- [ ] 同母代理下玩家的贏分事件會出現在活躍玩家資訊（不設門檻，小額贏分也收錄）。
- [ ] 訊息上行玩家資訊比照玩家 Chip：背板底色 + 等級 + 稱號 + 名稱。
- [ ] 無新訊息時，顯示區停留在最後一則，不清空、不隱藏。
- [ ] 玩家完成當日**全部**每日任務時，該事件出現在活躍玩家資訊；只完成部分任務不出現。
- [ ] 贏分訊息為兩行式：上行玩家資訊、下行 `Win x{倍數}`；**不顯示贏分數值（金額）**。
- [ ] 完成每日任務訊息為兩行式：上行玩家資訊、下行固定英文文案（暫定 `Daily Tasks Complete`）。
- [ ] 贏分 ≥ 20 倍的事件同時出現在活躍玩家資訊與一般跑馬燈（兩區皆顯示）。
- [ ] 玩家自己的事件在自己畫面的兩個顯示區照常顯示。
- [ ] 訊息每 3 秒輪播一則。
- [ ] 明顯過舊（約超過 1 分鐘）的訊息不再顯示（約略值，不要求精準到秒）。
- [ ] 待播訊息明顯超量（約 20 則）時，舊訊息被捨棄、不補播（約略值，不要求精準則數）。
- [ ] 玩家名稱含特殊字元不破版、無 XSS。

### 一般顯示（獨立跑馬燈）

- [ ] 贏分倍數 ≥ 20x 時觸發跑馬燈；19x 及以下不觸發。
- [ ] 贏分訊息格式：〔使用者資訊〕〔遊戲名稱〕`Win x{倍數}`；不顯示贏分金額。
- [ ] 玩家從 50 名外上升到 50 名內時觸發進榜訊息；格式〔使用者資訊〕〔排行榜名稱〕`entered the top 50`。
- [ ] 已在 50 名內的名次變動（如 30 → 10 名）**不觸發**跑馬燈。
- [ ] 進榜判定僅通用總排行榜；進入**遊戲各別排行榜**前 50 名**不觸發**。
- [ ] 一個行為同時進多個指標榜時，每榜各發一則訊息（不過濾、不合併）。
- [ ] 排行榜每月重置後 6 小時內不發上榜訊息；6 小時後恢復正常判定。
- [ ] 解鎖稱號 / 解鎖成就**不觸發**跑馬燈。
- [ ] 多則訊息依到達順序播放，無插隊。
- [ ] 一般跑馬燈僅對**同母代理**玩家廣播。
- [ ] 玩家領取週獎勵當下觸發週打卡訊息（暫定 `Weekly Check-in Complete`）；只達成未領取不觸發。
- [ ] 玩家領取月全勤獎當下觸發月打卡訊息（暫定 `Monthly Check-in Complete`）；只達成未領取不觸發。
- [ ] 次月補領上月週獎 / 月全勤獎時，同樣觸發對應廣播。
- [ ] 跑馬燈內所有訊息文案為英文，無中文文案露出。
- [ ] 訊息文字過長時截斷顯示 `…`，不破版。
- [ ] 系統公告可透過 API 新增（識別碼 / 訊息 / 持續時間 / 頻率）並在跑馬燈播放；訊息不帶玩家資訊。
- [ ] 系統公告可透過 API 以識別碼**更新**內容、**移除**後不再播放。
- [ ] 系統公告於持續時間內依「頻率」每 N 秒插播一次；持續時間到期後不再播放。
- [ ] 新增公告未帶持續時間 / 頻率時，採預設值（10 分鐘 / 20 秒）。
- [ ] 一般訊息常態以每 3 秒一則的節奏播放。
- [ ] 跑馬燈開合動畫正常：展開 → 單則滑動 → 收合 → 播下一則。
- [ ] 無待播訊息時跑馬燈維持收合，不顯示空容器。
- [ ] 訊息中的使用者資訊比照玩家 Chip（背板 + 等級 + 稱號 + 名稱）。
