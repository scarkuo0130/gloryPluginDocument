> 文件建立日期：2026-04-27

## 一、文件閱讀方式

- 本文件描述「系統行為與規則」，**不規範**程式架構、技術選型、檔案分層。
- 凡標註 `TBD` 之數值或規則，代表企劃尚未拍板，實作時請先以**預設值**開發並抽參數，待確認後可直接替換。
- 凡標註 `必要` 的條件，未滿足時整個流程**不得進行**；標註 `建議` 之行為若有技術困難可協商替代方案。

## 二、系統定位與邊界

1. 本系統以 **Game Plugin** 形式掛載於既有專案（Stream n' Spin、IDN Slot…）。
2. 與既有專案**邏輯隔離**：
   - 不修改既有專案的遊戲邏輯、下注流程、結算流程。
   - 僅以「監聽事件 + 浮動 UI」的方式存在。
3. 既有專案僅需提供：
   - 玩家身分（識別玩家是誰）
   - 下注 / 派彩 / 中獎事件（用於更新等級、任務、跑馬燈）
   - 餘額（若需顯示）
4. 本系統**不直接操作**既有專案的餘額。任何金流變動仍由既有專案負責。

## 四、玩家資料邏輯

### 4.1 玩家欄位（必須維護）

- 玩家名稱（顯示用）
- 等級 `Lv`（整數，從 1 起算）
- 經驗值 `EXP`（整數，僅內部使用，**畫面不顯示數字**）
- 頭像（使用者選擇 / 解鎖獲得）
- 稱號 Title（使用者選擇 / 解鎖獲得）
- 背板 Background（使用者選擇 / 解鎖獲得）
- 已解鎖頭像清單
- 已解鎖稱號清單
- 已解鎖背板清單
- 未讀信箱數
- 各排行榜累計值（TurnOver、得分）

### 4.2 等級與經驗值

| 規則 | 內容 |
|---|---|
| 升級條件 | `TBD`，預設：每級需 `1000 × Lv` EXP |
| 最高等級上限 | `TBD`，預設無上限，但 UI 顯示需能容納 3 位數 |
| EXP 取得來源 | 每日任務、成就、`TBD`：是否含下注回饋 |
| EXP 是否可扣 | 否（單調遞增） |
| 升級瞬間 | 必要：觸發升級動畫 + 解鎖檢查（解鎖機台、頭像等） |
| 顯示方式 | 必要：僅顯示 EXP Bar 比例，不顯示數字、不顯示「目前/下一級」數字 |

### 4.3 解鎖規則

- 頭像、稱號、背板都屬於「外觀類資產」，**不可在解鎖前選用**。
- 解鎖來源（依優先級）：
  1. 系統初始（每位玩家預設擁有的）
  2. 等級解鎖
  3. 成就解鎖
  4. `TBD`：商城 / 活動
- 解鎖後**永久持有**，不會被回收。

## 五、Account Status Bar（左上角狀態列）

### 5.1 顯示元素（由上而下）

1. 頭像（含等級徽章 `Lv.XX`）
2. 玩家名稱
3. 稱號 Title
4. 經驗值 Bar（**不顯示數字**）
5. 背板（作為整條 Bar 的底色）
6. 紅點（附在頭像右上角，內含未讀數）

### 5.2 不得顯示

- ❌ 玩家 ID
- ❌ EXP 數字
- ❌ 信箱 Icon
- ❌ 餘額（餘額顯示交由既有專案）

### 5.3 互動規則

| 動作 | 結果 |
|---|---|
| 點擊整條 Bar | 展開主選單 |
| 點擊右側 `‹` 按鈕 | 整條 Bar 平移收到畫面外，僅露出 `›` 拉柄 |
| 點擊 `›` 拉柄 | Bar 重新平移回原位 |
| 收合期間有新跑馬燈 | 跑馬燈仍照常播放，不受 Bar 收合影響 |
| 收合期間有新未讀信件 | 紅點數字累加，但 Bar 收合中不顯示；展開時直接以最新數字呈現 |

### 5.4 紅點規則

- 顯示條件：未讀信件數 > 0。
- 顯示內容：未讀數；超過 99 顯示為 `99+`。
- 清除條件：玩家進入信箱頁並讀取對應信件後，該信件即標記為已讀。

## 七、各頁面邏輯

### 7.1 個人資料頁

頁面分為三段，由上而下：

1. **頭像選擇區**：列出已解鎖的頭像，可點選切換。
2. **稱號選擇區**：位於頭像與背板之間。列出已解鎖稱號，可點選切換；可選「無稱號」。
3. **背板選擇區**：列出已解鎖背板，可點選切換。
   - 必要：切換背板後，Status Bar、主選單表頭、排行榜中代表自己的那一列皆需即時同步。

**規則：**
- 不顯示 email。
- 暱稱本期**不開放修改**（`TBD`：未來是否開放）。
- 切換動作即時生效，不需要「儲存」按鈕；但需呼叫後端寫入。
- 鎖定中的資產顯示為灰階 + 鎖頭，點擊時顯示**解鎖條件**提示，不可選用。

### 7.2 信箱頁

| 項目 | 規則 |
|---|---|
| 排序 | 必要：依時間倒序（最新在上） |
| 已讀標記 | 開啟某筆訊息後，立刻標為已讀並更新紅點 |
| 訊息類型 | 系統訊息、活動通知、成就達成通知、`TBD`：個人對個人訊息（本期不做） |
| 保留期限 | `TBD`，預設保留 30 天 |
| 批次操作 | 本期不做（不提供「全部已讀」） |

### 7.3 排行榜頁

- Tab 切換：**TurnOver 排行榜** / **得分排行榜**。
- 每筆顯示：
  - 名次（前 3 名特殊樣式：🥇🥈🥉）
  - 玩家頭像
  - 玩家背板（作為該列底色或左側色條）
  - 玩家稱號
  - 玩家名稱
  - 玩家等級
  - 排行數值
- 必要：**不得顯示經驗值**。
- 自己所在的列必要以**目前的背板**呈現（與 Status Bar 同步）。
- 更新頻率：`TBD`，預設**每 5 分鐘**更新一次或玩家進入頁面時拉取。
- 名單長度：`TBD`，預設 Top 100。
- 同分處理：`TBD`，預設以達成時間先後決定排名。

### 7.4 成就 / 任務頁

頁面分兩段：

#### A. 每日任務

- 任務列表 + 進度條 + 領取按鈕。
- 完成條件：累計達成（不需單局）。
- 重置時間：`TBD`，預設每日 00:00（伺服器時區）重置。
- 領取後給予 EXP，EXP 累積即可能升級。
- 未領取的任務在重置時若未完成則進度歸零；已完成未領取的處理方式 `TBD`（建議：保留可領取直到下次重置前）。

#### B. 遊戲攻略成就

- 成就為**永久性**，達成後不可取消。
- 成就分類方式需與排行榜一致，至少包含：
  - **總成就**
  - **各別遊戲成就**
- 總成就承接跨遊戲、跨場景的整體累積表現。
- 各別遊戲成就承接單一遊戲的專屬條件與攻略進度。
- 每個成就皆有 6 個等級，階級由低到高為：
  - 銅
  - 鐵
  - 銀
  - 白金
  - 黃金
  - 鑽石
- UI 顯示順序可依情境調整，但資料結構需保留完整 6 階門檻。
- 達成瞬間：
  1. 推播跑馬燈（依跑馬燈規則）
  2. 寄送系統信件（含獎勵內容）
  3. 解鎖獎勵（頭像 / 稱號 / 背板）
  4. 顯示彈出提示（若玩家在線）
- 首批數值型成就範例：

| 成就名稱 | 指標 | 銅 | 鐵 | 銀 | 白金 | 黃金 | 鑽石 |
|---|---|---:|---:|---:|---:|---:|---:|
| 彩金獵人 | Payout 得分 | 20,000 | 400,000 | 6,000,000 | 80,000,000 | 1,000,000,000 | 20,000,000,000 |
| 幸運兒 | Payout 倍數 | 20x | 50x | 100x | 150x | 250x | 500x |

- 成就清單（首期，可擴充）：

| 成就 | 條件 | 獎勵 |
|---|---|---|
| 梅杜莎獵手 | 在「梅杜莎」達成 Win × 50 | 頭像 🐍 |
| Tiger Cop 獵手 | 在「Tiger Cop」達成 Win × 50 | 頭像 🐯 |
| TurnOver 達人 | 單日 TurnOver 達 1,000,000 | 頭像 🐲 + 背板 熔岩 |
| 幸運大獎 | 單局派彩 500x | 頭像 👑 + 稱號「幸運兒」|
| 機台收藏家 | 解鎖 20 台機台 | 頭像 🎰 + 背板 賭場 |
| 連勝王 | 連續贏取 10 次 | 頭像 🔥 + 稱號「不敗」|
| 直播之星 | 累積在直播間下注 100 萬 | 頭像 🌟 + 背板 星河 |

- 「連勝」定義：派彩 > 0 算一次勝利，派彩 = 0 中斷連勝。
- 「累積在直播間下注」需由 Stream n' Spin 提供下注事件並標註為 live 場景。

### 7.5 機台選擇頁

#### 機台解鎖規則

- 等級 5 → 5 台可選；等級 10 → 10 台可選。
- 一般通則：**等級 N → 可選 N 台**（上限 `TBD`，預設 50）。
- 已解鎖的機台**永久解鎖**，即使等級因任何原因被調整。

#### 頁面結構

1. **頂部「目前機台」大卡片**：
   - 機台編號 `#XX`
   - 資料區間 `YYYY-MM-DD ~ YYYY-MM-DD`
   - Turnover
   - Total Win
2. **分隔線**
3. **可選機台清單**，每筆顯示同上四欄。

#### 互動規則

- 點擊清單某一台 → 將該台資料**替換**到頂部「目前機台」卡片。
- 必要：機台**不顯示圖片**，純文字呈現（首期暫不放縮圖）。
- 數據顯示：千分位逗號（範例：999,999,999）。
- 若顯示資料（Turnover / Win）為**模擬資料**：開發期可寫死，正式期 `TBD`：是否串接真實統計資料（建議：先以後端假資料介面提供，未來可改真資料）。

## 八、跑馬燈邏輯

> 本章已於 2026-06-10 依《`跑馬燈系統規格.md`》口述決議更新；兩文件如有出入，以《跑馬燈系統規格.md》為準。

### 8.1 觸發來源

| 觸發 | 條件 |
|---|---|
| 高倍贏分廣播 | 單局贏分倍數 ≥ **20x**（只看倍數，不看金額） |
| 進入排行榜前 50 名 | 從 50 名**外**上升到 50 名**內**才觸發；榜內名次變動不觸發；僅**通用（全部）排行榜**，遊戲各別排行榜不列入 |
| 完成週打卡 | 玩家**領取週獎勵**當下觸發（非達成當下） |
| 完成月打卡 | 玩家**領取月全勤獎**當下觸發（非達成當下） |
| 系統公告 | 營運透過 API 發出（維護通知 / 活動通知 / 系統通知）；第一階段無後台畫面 |

> 原列之「解鎖稱號」「解鎖里程碑成就」廣播已**取消**（口述決議）。

### 8.2 訊息內容（每筆訊息以「玩家 Chip」呈現）

每筆 Chip 必含：
- 該玩家**目前的背板**作為 Chip 底色
- 等級徽章 `Lv.XX`
- 稱號 Title
- 玩家名稱
- 訊息文字（例：`中得 100,000,000`）
- 主題 emoji（依訊息類別）

系統公告類訊息**不帶玩家 Chip**，僅顯示公告文字。

### 8.3 播放規則

- 每次只播 **1 則**（不串接、不疊放）。
- 常態播放節奏：**每 3 秒一則**。
- 依**到達順序**播放，不做優先序、不做同類合併。
- 設計上不希望佇列堆積；常態性堆積屬設計警訊，應檢討並**提高顯示條件**（如調高贏分倍數門檻）。

### 8.4 動畫流程（必要）

1. 預設狀態：marquee 收合（不可見、不擋觸控）。
2. 收到訊息 → marquee **彈跳展開**（橫向）。
3. 容器展開後 → 內容由右滑入到左**單次**滑動。
4. 滑完後 → marquee **收合消失**。
5. 自動播放下一則。
6. 若隊列為空 → 維持收合狀態，不顯示空容器。

> 單則總週期配合常態節奏「**每 3 秒一則**」；展開 / 滑動 / 收合各段時長由實作調配。（舊版 prototype 預設「展開 0.45s + 滑動 6s + 收合 0.45s + 間隔 1.2s ≈ 8 秒週期」已**作廢**。）

### 8.5 與 Status Bar 的互動

- marquee 在 Status Bar 下方獨立顯示，**不被 Bar 收合影響**。
- marquee 顯示時，玩家點擊既有遊戲區域**不被 marquee 攔截**（marquee 區塊 pointer-events 視情況關閉）。

## 十、Plugin 整合行為

### 10.1 初始化流程

1. 既有專案載入 plugin。
2. plugin 向既有專案要玩家身分。
3. plugin 拉取玩家資料（等級、頭像、稱號、背板、未讀數、各任務 / 成就 / 排行榜累計）。
4. plugin 渲染 Status Bar。
5. plugin 開始監聽既有專案事件。

### 10.2 既有專案需提供之事件（最小集合）

| 事件 | 用途 |
|---|---|
| 下注 | 累計 TurnOver、任務進度 |
| 派彩 | 累計得分、判斷大獎廣播、連勝計算 |
| 場景識別（live / non-live） | 直播之星等成就 |
| 玩家登入 / 登出 | plugin 自身的顯示與資料拉取 |

### 10.3 隔離原則

- plugin **不得**直接讀寫既有專案的金流、餘額、注單。
- plugin 自有資料以 plugin 後端為準；不依賴既有專案資料庫。
- plugin 異常**不得**導致既有專案崩潰；必要：所有渲染、事件處理需有 try-catch 保護。

## 十一、邊界條件與例外

| 情境 | 預期行為 |
|---|---|
| 玩家無頭像 / 無背板 / 無稱號 | 必要：以系統預設值呈現，不可空白 |
| 排行榜尚無資料 | 顯示「目前無排行資料」空狀態 |
| 信箱無訊息 | 顯示「目前沒有訊息」空狀態 |
| 機台清單尚未解鎖任何台 | 頂部「目前機台」顯示預設機台；下方清單顯示等級不足提示 |
| 後端拉取資料失敗 | 必要：UI 不可崩潰；以快取或上次成功值顯示，並在角落顯示重試提示 |
| 跑馬燈訊息文字過長 | 必要：限制最大字數（`TBD`，建議 60 字），超過截斷加 `…` |
| 玩家名稱包含特殊字元 | 必要：HTML escape，禁止 XSS |
| 等級徽章顯示 3 位數 | 必要：UI 寬度需容納 `Lv.999` |

## 十二、驗收要點（QA 自查清單）
