## 2. 功能流程

### 2.1 每日任務領取流程

1. **任務達成**：遊戲事件累積 `progress` 達 `target`，`status` 轉為 `claim`（可領）。
2. **點領取**：`claimTask(id)` → `status` 由 `claim` 改 `done`。
3. **發放**：給予該任務 `exp`（接等級系統 EXP），播成功音效，跳 toast「+N EXP」。
4. **更新**：重渲染任務清單 + 主選單紅點 + 選單進度條。

### 2.2 連簽領取流程

1. **當日達成**：當天「3 個每日任務全領完」(`allTasksClaimed`) → 當天格子點亮 (`done`)。
2. **整週判定**：該週 7 天皆 `done` 且無漏簽 → 該週「領取」鈕啟用。
3. **領週獎**：`claimStreakReward(週index)` → 發 EXP，標記已領（`streakClaimedGroups`），鈕轉「已領取」。
4. **斷簽**：任一天漏簽 → 該週鈕顯示「未達成」鎖定，**無法補領**。
5. **全勤獎**：4 週（28 天）全 `done` → 四週額外獎可領 → 頭像 🏆。

### 2.3 每日重置（TBD，企劃未定）

- 每日 00:00：任務 `progress` 歸零、`status` 重置。
- 伺服器時區、過期未領的處理方式待企劃拍板。

## 3. 資料設定

### 3a. 每日任務資料結構 `dailyTasks[]`（index.js）

| 欄位 | 型別 | 說明 |
|---|---|---|
| `id` | number | 任務唯一識別 |
| `title` | string | 任務名稱（顯示） |
| `exp` | number | 完成領取給予的 EXP |
| `progress` | number | 目前進度 |
| `target` | number | 完成所需目標值 |
| `status` | `'claim'` \| `'done'` \| 其他 | claim=可領, done=已領, 其他=未完成(disabled) |

### 3b. 目前 demo 任務（寫死值）

| id | 任務 | EXP | 進度 | 狀態 |
|---|---|---|---|---|
| 1 | 登入打卡 | 50 | 1 / 1 | claim |
| 2 | Spin 10 次 | 80 | 10 / 10 | claim |
| 3 | Win 1 次 | 120 | 1 / 1 | claim |

### 3c. 連簽參數（index.js `STREAK_*`）

| 參數 | 值 | 說明 |
|---|---|---|
| `STREAK_REWARDS[0]` 第 1 週 | EXP +500 | 該週 7 天全勤可領 |
| `STREAK_REWARDS[1]` 第 2 週 | EXP +1,000 | |
| `STREAK_REWARDS[2]` 第 3 週 | EXP +1,500 | |
| `STREAK_REWARDS[3]` 第 4 週 | EXP +2,000 | |
| `PERFECT_ATTENDANCE_REWARD` | 頭像 🏆 | 28 天全勤額外獎 |
| `STREAK_DAYS_PER_GROUP` | 7 | 每組（週）天數 |
| `STREAK_TOTAL_DAYS` | 28 | 4 週合計 |
| 當日完成判定 | `allTasksClaimed` | 當天 3 個每日任務全部領取完成才算該日 done |

### 3d. 殘留 / 待清（程式提醒）

## 4. 實作備註

- 本頁所有 UI 為 `file://` / GitHub Pages 純前端渲染，資料皆前端 mock；正式版任務進度、連簽狀態、獎勵發放須由後端提供與寫入。
- 玩家名稱等動態文字需 HTML escape，避免 XSS。
- EXP 不顯示數字（沿用狀態列規格），僅以 Bar 比例呈現；每日任務的 `+N EXP` 為領取回饋文案，非常駐顯示。
